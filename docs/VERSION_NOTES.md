# 版本记录 / Version Notes

本文件由各历史版本的 `module.prop` 描述自动汇总而成，是完整的开发过程记录。
按版本号升序，重复的描述只保留首次出现。

---

## v2  —  version `0.1` / versionCode `1`

Brings LG's com.lge.ims ImsService + product.lge.data.server. No APK modification, no substrate image. First test build - VoLTE only, no VoWiFi.

## v8  —  version `0.8` / versionCode `8`

v0.8: 补上 LG 留在 system_ext/lib64 的 HAL 接口库 (vss_ims/lgdata) 以修复 libims.lge.so dlopen 失败；移除导致 MLS 不匹配的 seapp 覆盖；对两个 APK 做字节码修补，替换 Android 14 已删除的 LG 扩展 API。VoLTE only.

## v10  —  version `0.10` / versionCode `10`

v0.10: 修掉最后一个方法缺口 SubscriptionManager.getSimStateForSlotIndex（LG 把它转发到 SubscriptionManager，A14 只在 TelephonyManager 上有）；补 radio 域对 default_android_hwservice 的 find（soi/touch HAL）。此版起 com.lge.ims 已能常驻并输出 LGIMS 日志。VoLTE only.

## v11  —  version `0.11` / versionCode `11`

v0.11: APK 与 v0.10 完全相同（v0.10 已消灭全部 NoSuchMethodError，两个进程 PID 稳定不再重启）。本版只重做诊断：logcat 只 dump 一次再反复 grep、两阶段采样、重点输出框架侧 ImsService 绑定与注册日志。VoLTE only.

## v12  —  version `0.12` / versionCode `12`

## v13  —  version `0.13` / versionCode `13`

## v20  —  version `0.20` / versionCode `20`

v0.20 诊断版，【不修改框架】。自检发现 v0.19 的判断有误：PE 的 plat_service_contexts 第438行是通配符 "* u:object_r:default_android_service:s0"，servicemanager 的权限检查又在查服务之前，所以【未注册的服务同样会产生 find 被拒的 AVC】—— 那条 AVC 不能证明 com.lge.ims.phone 存在。离线核对：PE 的 telephony-common/framework/services.jar 里 LGImsPhoneService、ImsFeatureProvider、hasLgeFeatureIms、ImsSmsService 全部为 0；PE 的 PhoneFactory.makeDefaultPhones 只有一行委托，没有任何 LG 钩子；全盘只有 LGImsPhoneService 自己含 "com.lge.ims.phone" 这个字符串。也就是说我们注入了 1592 个类，却没把调用点注进去 —— com.lge.ims.phone 很可能从未注册过。本版只做三件事把这件事在设备上钉死：(1) 从 post-fs-data 起持续过滤抓取 logcat 到 v50ims_lg.txt（v0.19 的 logcat -d 采样已滚过关键窗口）；(2) 放开 log.tag.LGIMS，让 ImsPhoneProxyManager 打出 "bindService :: 值"；(3) 快照里跑 service list，直接看服务在不在，并汇总 avc denied 与 LG 原生引擎跑到哪一步。另补 6 条 default_android_service 的 SELinux 规则（服务一旦真被注册，find 就是真的会被拒）。

## v21  —  version `0.21` / versionCode `21`

v0.21 打上 PE 缺失的框架调用点：PhoneFactory.makeDefaultPhones -> LGImsPhoneService.create(ctx, sPhones, sCommandsInterfaces)。原厂 A12 的 PhoneFactory.makeDefaultPhone 末尾有这段，PE14 完全没有（telephony-common/framework/services.jar 里 LGImsPhoneService、ImsFeatureProvider、hasLgeFeatureIms、ImsSmsService 全部为 0），所以我们注入的 1592 个类从来没被调用过，binder 服务 com.lge.ims.phone 从未注册。v0.20 实测证据：LGIMS_IPPM: bindService :: null、LGIMS_IPS 0 行、service list 无该服务、ApnImsGlobal 打出 vops=off。因果链：缺钩子 -> 服务不注册 -> ImsPhoneProxyManager.getPhoneProxy 返回 null -> 29 个类静默降级（含 IIMSPhoneGov$IImsPhone.mPhoneProxy）-> VoPS 通知永不送达 -> DCNetWatcher.mIMSVoPS 恒 false -> 条件位 VOLTE_VOPS_ON(0x4) 不置位 -> 不发 SIP REGISTER。补丁只改 makeDefaultPhones 这一个 6 行方法，带 sPhones 非空判断和 catchall 兜底。telephony-common.jar 在 boot classpath 上，所以带开机失败自动回退：连续 2 次没走完开机就把补丁 jar 移出 system/，下一轮自动恢复原版；救急可用 APatch 安全模式。

## v22  —  version `0.22` / versionCode `22`

v0.22: 把 LG 桥接类真正放上 boot classpath。v0.21 的日志证明补丁执行了、magic mount 生效了、异常被 catchall 接住了，但抛的是 NoClassDefFoundError: Class not found using the boot class loader —— 因为 lgdataservice-manager.jar 是通过 <library> 声明的 shared library，只挂进应用的 class loader，boot classpath 看不见（我此前拿 Ims6.apk 能调用它反推它在 boot classpath 上，漏掉了这条机制）。本版把 closure3 里 1546 个类（1592 减去 46 个与 boot classpath 重名的 android/net/* 网络统计类）汇编成 classes2.dex 放进 telephony-common.jar —— 与 framework.jar 放 classes.dex~classes5.dex 同一机制，PhoneFactory 与 LGImsPhoneService 同属 BootClassLoader，直接解析。离线校验：classes.dex 2570 类只有 PhoneFactory 有实质差异（5 个仅 boolean=false 归一化），classes2.dex 1546 类逐类与源码一致且与 46 个重名类无交集，闭包外部引用补上 APEX 后剩 0 个无法解析。安全网（连续 2 次没走完开机就自动移出补丁 jar）与 v0.21 相同。

## v29  —  version `0.29` / versionCode `29`
